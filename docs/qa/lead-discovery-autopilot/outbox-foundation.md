# Lead analysis outbox foundation — NO-GO

Collection can persist versioned hints only for a source with explicit source-specific opt-in (default off), current AI grant and an actor who passes an analyze permission preflight. The preflight runs outside the ingestion transaction to avoid holding locks during authorization I/O. Within the transaction, enabled configuration and source grant/actor are checked again; changed publication and hint commit or roll back together. Hint records are `WAIT_AUTH_RECHECK`, contain no post text, and are never dispatchable. There is no worker, timer, public opt-in switch or provider call in this slice. The collection button does not enable it.

The permission preflight is not atomic with role revocation. Binding revision fences source rebinding, but membership and own-channel catalog races remain unresolved. Before any dispatch, introduce coordinated authorization and ownership locks/versions, recheck current policy and source binding, and define the in-flight cancellation, budget and uncertain-provider-result semantics. A transient preflight database error deliberately fails closed without interrupting collection; the transaction records a source gap and generation instead of silently forgetting the missing hint. Source opt-in marks a bounded cursor-based pass over existing retained observations as needed. This pass is an internal explicit service only, with no endpoint or automatic wake, so gaps are not automatically recovered. Durable cross-instance wake/recovery remains required before claiming automatic processing works. Membership, ownership and grants must be fenced again before any future consumer is enabled.

An edit or deletion removes stale waiting hints even when the source is disabled or a grant was revoked. Unchanged content causes no outbox write. The queue and its source/tenant relationship are database constrained, and deleting an expired observation cascades to its hints. Observations are retained for 90 days; this is the queue retention ceiling. The existing workspace quota allows up to 10,000 new observations per day, while the outbox is capped at 5,000 waiting hints per source and 50,000 per workspace; 100 sources with 300 posts each can add 30,000 hints. Overflow marks the gap and is recorded in the source configuration without blocking collection. Catch-up uses pages of at most 100, a stable upper bound, a cursor and a generation check; it stops without advancing when capacity is exhausted and clears overflow only after a complete stable pass. Binding revision changes remove only stale WAIT_AUTH_RECHECK hints and mark a gap for enabled sources using a database trigger. Observations and AI receipts are untouched; disabled sources also discard stale hints and a future re-enable requires a new pass. Repeated blocked pages do not update the checkpoint or generation. Enabled ingestion performs one batch preflight read, one config check and at most one insert per batch, plus a stale-hint delete for edits; disabled ingestion still does the bounded preflight read. There is no idle polling, recurring job, provider traffic or separate queue worker CPU. A future producer needs fair bounded batches and visible overflow/catch-up handling; the overflow timestamp is not yet exposed by an API or UI.

Internal opt-in changes must go through `TelegramLeadReconciliationService.setEnabled` to start catch-up; direct writes bypass this contract. No user-visible status exists yet. Full PostgreSQL concurrency tests for enable/disable, membership revocation and own-channel changes remain outstanding, and the workspace count query can scan up to 50,000 hints per active batch and needs a cost benchmark.

Lock ordering: existing ingestion and reconciliation obtain the workspace advisory lock, then source row locks. Source rebinding triggers discard old waiting hints before touching the config row; subsequent work must not reverse the source-to-queue/config ordering. AI receipt work and a future consumer need their own reviewed lock ordering.
