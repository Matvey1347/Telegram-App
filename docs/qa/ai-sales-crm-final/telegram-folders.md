# Telegram CRM folders

The Inbox shows account-scoped Telegram folders beside the chat list, with message-level unread totals over the full authorized, active dataset. Global Unread clears the selected folder. Folder membership is stored per conversation, independent of CRM contact creation and the selected contact-import tags. Overlapping folders are counted independently; archived and inaccessible conversations are excluded. `excludeRead` is evaluated from the current unread state, and the UI reconciles read/new-message transitions without polling.

A conversation is automatically marked read only when the browser tab is visible, history and recent synchronization succeeded, the message is actually visible near the bottom, and no modal obscures the conversation. The request carries the highest visible numeric Telegram message ID. The API scopes and caps the read to that ID, preserving later arrivals; an error is not retried automatically. Manual retry remains available.

The additive migration seeds only known account-scoped contact-tag memberships. Existing unlinked membership requires a bounded, explicit one-time account sync after deployment. Folder definition and membership refresh after Telegram-side changes is event-driven and bounded; no periodic job or additional Telegram session is introduced.

Verification so far: actual migration and the real Prisma aggregate service ran against isolated PostgreSQL 17. Fixtures covered linked and unlinked chats, overlapping folders, archived messages, separate accounts, foreign workspaces, ownership scope, seed preservation, FK rejection and cascade. Revision columns were verified to default to zero, and a conditional acknowledgement could not clear a newer revision. The disposable server was stopped and removed. A focused comparison against Prisma-generated SQL confirmed the new table columns, indexes and foreign-key names match the schema. Required full checks retain the existing baseline: API 13 failing suites / 23 tests, web 19 failing files / 29 tests, web lint 142 errors / 168 warnings, architecture 22 standard and 28 strict failures. No new architecture failure appeared. The API and web builds, typechecks and focused suites passed. The repository's historical full migration bootstrap limitation remains documented in the existing CRM audit.

Runtime cost: one scoped folder-list read plus one grouped unread query and one global unread aggregate per active refresh; no per-folder query, idle polling, additional runtime, provider calls or retention policy. A 100-folder workspace still performs the same three reads; event-triggered updates are coalesced. Full account metadata scans occur on a true global Telegram folder change or to repair a durable pending change after owner reconnection, capped at 10,000 raw dialogs (100 pages); a clean reconnect does not scan, and an incomplete scan is never reported as complete. New private peers are refreshed in targeted batches of up to 100. One abort-aware 100 ms retry follows a transient failure, with durable pending state surviving restart and later retry on account activity. Up to three account scans run concurrently; ordinary chat reads and history fetches do not wait for folder scans. This is event/startup work, not an idle timer. The explicit initial backfill uses existing bounded dialog pages and the existing owner lease, with at most 2,000 scanned / 1,000 eligible dialogs per invocation. List reconciliation on reconnect or folder changes refetches the pages the user has loaded, so work scales with loaded pages rather than folder count. No recurring database write is introduced. Timed mute expiration without a Telegram update can leave affected folder membership stale until the next account folder reconciliation; the existing CRM scope is private Telegram conversations, not group/channel chats.

Manual QA: open Business Inbox, select a populated folder and verify its chats and badge; click Unread and verify the selection clears and all unread chats appear. Switch folders during a delayed load and verify no previous-folder rows appear. Open an unread chat at the bottom, confirm its count changes; open another in a hidden tab, behind a modal or while viewing old history and confirm it stays unread. Check automatic update after a Telegram folder edit, switch workspace, and verify no folder selection or count leaks between workspaces.
